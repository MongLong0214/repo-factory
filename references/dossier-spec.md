# Phase 2 상세 — 도시에(종합 보고서) 명세

단일 HTML 아티팩트. 사용 가능한 문서/아티팩트 도구가 있으면 사용하고, 없으면 repo-local HTML을 생성해 브라우저로 검증한다. 문서형 유틸리티 트리트먼트(타이포 위계·여백·절제된 팔레트)를 유지한다.

## 섹션별 필수 요소

### 0. Executive Summary
3문단 고정: **실체**(대상이 실제로 무엇인가 — 과장 없이) / **그럼에도 옳은 것**(핵심 통찰 1개) / **고도화 방향**(결함 n건 → 계층 아키텍처 → 배포 경로). 마지막에 한 줄 차별점.

### 1. 대상 해부
- **실체 목록** — 파일 단위 표. "실행 가능 코드" 열을 반드시 둔다
- **약속 대비 구현 매트릭스** — 원 논문/문서가 명세한 것 vs 실제 배달된 것
- **결함 목록** — 카드 형식. 각 카드: `ID · 분류` / 한 줄 제목 / 서술 / **수정 방향(어느 계층에서 해소되는지)**. 재현된 것은 `재현됨` 배지
- **그럼에도 옳은 것** — 최소 2~3개. 이게 없으면 프로젝트를 할 이유가 없다

### 2. 학술 지형
- 시대별 계보 (4기 정도로 분할)
- **경쟁 삼각 구도** — 축이 다른 접근들을 표로. 배타적이지 않고 축이 다르다는 점을 밝히면 통합 전략이 보인다
- **반증 증거와 설계의 응답** ⚠️ 필수 — 가장 불리한 증거부터
- 이론적 뒷받침 — "왜 지금인가"

### 3. 차용 검토 보론 (오너 제공 자료별)
자료마다 §2.x 보론. 판정표 + 차용분의 귀속 위치 + 기각 사유.

### 4. 아키텍처
- 설계 원칙 n개 — **각 원칙이 §1 결함에서 도출됨을 명시** (원칙 → (결함 ID) 매핑)
- 계층도 (mermaid)
- 계층별 상세 — 무엇을, 왜, 어떤 결함을 해소하는지

### 5. 배포·채택 전략
- 경쟁 지형표 + 한 줄 포지셔닝
- 채택 경로 (Phase A/B/C)
- **도입 적격성 테스트** — 모두에게 팔지 않는다. 부적격 도입의 조용한 실패가 최악
- **리스크 대장** — 리스크 / 확률 / 완화. 지속가능성·프라이버시·표준 선점은 기본 항목

### 6. 로드맵
마일스톤 표 (기한·배달물·완료 기준). **기한 압축 시 자른 것을 명시**.

### 7. 참고문헌
축별 표. **검증된 DOI/ID만.** 각 축에서 가장 하중이 실리는 문헌 1~2편을 하이라이트.

### 8. 부록
- **재현 실험 로그** — 터미널 스타일 블록, 명령어+출력 그대로
- 산정 근거 (오너가 배율·수치를 요구했다면 정직하게 계산해 보이기)

## 톤 규칙

- 단정형. "~로 보인다" 대신 "~다" 또는 "확인되지 않았다"
- 대상을 깎아내리지 않는다. 결함은 결함대로, 옳은 것은 옳은 대로
- 모든 강한 주장 옆에 근거(재현 로그·문헌 ID·API 응답)를 붙인다
- 오너가 수사(修辭)로 요구한 것(예: "16.8배")도 성실하게 계산해 보여준다 — 계산 불가면 그렇게 말한다
